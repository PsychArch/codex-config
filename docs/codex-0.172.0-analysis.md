# Codex 0.172.0 drift analysis

This release retargets `codex-config` from Codex 0.171.0-alpha.5 to stable 0.172.0 at commit `3d86e43b075adeba2193ec5c22ac92f55afd82e6`. The bundled schema is copied byte-for-byte from the release, and compatibility metadata is generated from the same source. [Upstream release](https://github.com/openai/codex/releases/tag/rust-v0.172.0) · [Schema](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/core/config.schema.json)

## Models and migrations

GPT-6.2 Sol is the bundled default. The catalog grows from eight models to ten with GPT-6.2 Sol and Astra. Both have an 872,000-token catalog maximum and declare Codex 0.166.0 as their minimum client version. GPT-6.1 Sol remains supported and its catalog default context window rises from 272,000 to 500,000 tokens. Normal apply preserves explicit model choices and context overrides. Fresh and forced applies use GPT-6.2 Sol with the curated context requests. Codex caps the effective context and compaction threshold against live model metadata. [Model catalog](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/models-manager/models.json) · [Context calculations](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/protocol/src/openai_models.rs#L572)

The generated migration removes `features.code_mode_host_grpc` at the root and in legacy inline profiles. Local Code Mode hosts always use gRPC. The refreshed schema accepts explicit response processing, rollout trace limits, Code Mode heartbeats, per-tool connected-app approval reviewers, and the new TUI keybindings. Optional stdio MCP servers with cached tools start lazily by default. Explicit feature settings are preserved. [Feature registry](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/features/src/lib.rs) · [Release notes](https://github.com/openai/codex/releases/tag/rust-v0.172.0)

## Runtime validation

- **Rollout budgets.** An enabled budget requires one allowance and an explicit reminder threshold array, which can be empty. The two allowance fields are mutually exclusive even on a disabled budget. Reminder thresholds must be positive and strictly below the allowance. The validator keeps whole-token allowances and thresholds exact above `2^53` and matches Codex's rounding for fractional allowances. [Upstream validation](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/core/src/config/mod.rs#L3078)
- **Guardian V3.** The per-prompt instruction cap applies independently to routing and retrieval. Codex estimates one token per four trimmed UTF-8 bytes, rounded up. Codex ignores the instruction overrides and cap in project config. Guardian V2 elastic budget validation carries forward from the alpha. [Upstream validation](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/core/src/config/mod.rs#L3192) · [Layer filtering](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/config/src/loader/mod.rs#L1374)
- **Transparent TCP.** An explicitly enabled proxy with transparent TCP requires SOCKS5. Single-file validation checks direct feature settings and the selected, non-inherited network-enabled profile, applying feature overrides. Inherited and managed policy are resolved by Codex. [Upstream proxy validation](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/network-proxy/src/state.rs#L63)

The validators report issues through `doctor` and reject invalid apply operations before writing. Validation covers the local configuration file. Provider authentication, managed policy, and session admission run in Codex.
