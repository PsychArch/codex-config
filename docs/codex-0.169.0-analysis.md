## Runtime evidence and defaults

- [`gateway_oauth.rs`](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/model-provider-info/src/gateway_oauth.rs) and [`lib.rs`](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/model-provider-info/src/lib.rs): OAuth/export source alternatives, device endpoint validation, delivery conflicts, same-origin enforcement, and shared `CredentialExportConfig`. Export timeout defaults to 30,000 ms. Secondary export credentials may accompany primary provider auth when delivery does not collide.
- [`core/config/mod.rs`](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/core/src/config/mod.rs) and [`guardian-context/budget.rs`](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/guardian-context/src/budget.rs): synchronous elastic allocation defaults off. Entry/minimum limits must be positive, entry caps cannot exceed the section minimum or 9,000 tokens, and an explicit section maximum cannot be below its minimum. Omitted sections contribute 5,000 transcript-message tokens, 1,000 transcript-tool tokens, and 900 for each of the other 11 sections. Effective minimums must total exactly 128,000. Aliases resolve before duplicate detection. When the activation switch is off, these runtime checks do not run; schema checks still apply.
- [`config/strict_config.rs`](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/config/src/strict_config.rs) and [`core/config/guardian_policy.rs`](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/core/src/config/guardian_policy.rs): user `extra_policy` and experimental full templates are no longer consumed. Enforced additional policy comes from `guardian_extra_policy` in managed requirements; supported `auto_review.policy` remains a fallback. No policy text is automatically discarded or reinterpreted here.
- [`config/loader/mod.rs`](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/config/src/loader/mod.rs): deprecated `multi_agent` still affects V1 fallback. `agents.enabled = false` disables subagent tools even when the model selects an agent version, unless `features.multi_agent_v2` is explicitly enabled. Layer precedence and model selection make a blanket rename incorrect.
- [`features/lib.rs`](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/features/src/lib.rs): code-mode gRPC, host output truncation, unified image budgeting, client tool-output retention, and untrusted tool-output context are stable and enabled by default. Guardian additional context and GCP incremental declarations are enabled by default. Legacy incremental declarations are stable but remain off and apply to Bedrock. Workspace, lazy stdio startup, animation, root-only background compaction, and denial reconsideration remain opt-in. Plugin discovery prefetch is a removed no-op.

Upstream also changes noninteractive project trust: `codex exec` and `codex review` require explicit saved trust to load project configuration and MCP servers. The `--trust` CLI option records that decision. `codex-config` does not infer trust from sandbox settings or add trusted project entries. Permission translation is centralized upstream without new serialized permission keys. Existing MCP readiness, network MITM, and provider override rules remain supported.
